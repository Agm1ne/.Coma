35. CANALES, FUTUROS Y SELECT (multihilo Fase 5) [OK]
- `canal crear Nombre.` crea un canal con buzón de 32 ranuras + backpressure (bloquea si está lleno). [OK]
- `canal enviar X a Nombre.` envía X al canal. Primitivos se copian; listas se transfieren por puntero fantasma (move semantics): el origen queda invalidado y usarlo después da E202 estático. [OK]
- `canal recibir X de Nombre.` recibe del canal en X. Bloquea si está vacío. [OK]
- `futuro X = expr.` evalúa expr de forma asíncrona y guarda el resultado en un canal interno llamado X. [OK]
- `esperar X.` espera a que el futuro X complete y trae su valor. [OK]
- `select { caso canal recibir X de C. => cuerpo. otro. => cuerpo. }` multiplexa sobre canales: ejecuta el primer caso cuyo canal tenga un mensaje disponible; `otro` es el caso por defecto. [OK]
- Nota: canales y actores comparten la infraestructura de buzones (ring buffer de 32 ranuras + 3 backups en RAM para depuración). [OK]

36. COMPILACIÓN CONDICIONAL (metaprogramación Fase 7) [OK]
- `si_compilacion condicion. ... sino_compilacion. ... fin_compilacion.` evalúa la condición en tiempo de compilación y descarta la rama inactiva antes de generar IR. Condiciones reconocidas: `windows`, `linux`, `debug`, `release`. Ejemplo:
  ```
  si_compilacion windows.
      mostrar "en Windows".
  sino_compilacion.
      mostrar "en Linux".
  fin_compilacion.
  ```
- La rama inactiva no se compila: no genera errores ni código. Útil para código específico de plataforma sin duplicar archivos. [OK]

40. RUNTIME SEPARADO (CORE vs EXTENSIONS) [OK]

41. CIERRES / CLOSURES (captura de entorno) [OK v1]
- Una función anidada puede capturar variables locales de la función que la contiene: `funcion Padre X. Contador igual 0. funcion Hija Y. Contador igual Contador mas Y. devolver Contador. fin. devolver Hija 5. fin.`
- Las capturadas se elevan a globales compartidas entre padre e hija (una por variable, nombre `@g_Contador`), así padre e hija leen/escriben la misma celda.
- Limitación honesta v1: no hay entorno separado por invocación (dos llamadas al padre comparten la misma capturada = no es reentrante). Para closures "de verdad" (heap + struct de entorno + puntero a función cerrado) hay que pasar a v2.
- Las variables capturadas deben ir con mayúscula inicial (`Contador`, no `contador`) para que el parser las reconozca como asignación.
- Tipos soportados como capturada: entero, decimal, texto. Listas, registros y asas no se capturan en v1 (E202 si se intenta).
- Una función anidada ve: sus propios parámetros, sus propias locales, las capturadas del padre y las globales.
- Demo: coma/tools/bateria/casos/ok_closure1.coma (imprime 5). [OK]
